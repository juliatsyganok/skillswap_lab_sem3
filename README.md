## Изменение контракта ЛР1

`InMemoryOfferStore.GetResponsesByUser` возвращает непустой по nil пустой slice, если откликов нет; вызывающая сторона может безопасно добавлять элементы в результат. Добавлены `SaveResponse` и `GetResponse` (плюс совместимые с `response.Repo` методы `Save`/`Load`); сохранение заменяет отклик с тем же ID, а чтение отсутствующего ID возвращает `ErrNotFound`. Данные выдаются как значения, а объекты хранилищ независимы. В `agreement.Service` повторное подтверждение уже принятого отклика теперь возвращает сохранённый статус без повторной записи.

## Сценарий demo

Сначала отклик pending у обеих сторон. Подтверждение переводит его в accepted и оставляет одну запись. Повторное подтверждение — no-op с одной записью. Чтение возвращает accepted.
